# DSPy

> In one minute: DSPy is an open-source Python framework, started at Stanford NLP, for programming language models instead of hand-writing prompts. You declare what each step does as a typed signature, choose a module that decides how to run it, and let an optimizer tune the prompts against a metric you define. Teams use it to make LLM pipelines easier to maintain, measure, and move between models.

## What it is for

- Classification, extraction, and summarization steps with typed outputs instead of fragile prompt strings.
- RAG and multi-hop pipelines built by composing modules in plain Python.
- Tool-using agents with `dspy.ReAct`.
- Automatic prompt optimization against a metric with optimizers such as GEPA, MIPROv2, and BootstrapFewShot.
- Porting a pipeline to a smaller or different model, then re-optimizing it.

## Quick start

1. Install DSPy (Python 3.10 or later).

   ```bash
   pip install -U dspy
   ```

2. Set your provider key as an environment variable. DSPy uses LiteLLM model strings in `provider/model` form, and the OpenAI provider reads `OPENAI_API_KEY` from the environment, so the key never appears in code.

   ```bash
   export OPENAI_API_KEY="your-api-key"
   ```

3. Configure a default LM and run a first program (from the official first-program tutorial).

   ```python
   import dspy

   lm = dspy.LM("openai/gpt-5-nano")
   dspy.configure(lm=lm)

   haiku_generator = dspy.Predict("subject -> haiku")
   result = haiku_generator(subject="computer science")
   print(result.haiku)

   dspy.inspect_history(n=1)  # show the prompt DSPy built
   ```

4. Use a class-based signature when you want typed fields and a docstring that becomes the instruction.

   ```python
   class ExtractEvent(dspy.Signature):
       """Extract event details from an email."""
       email: str = dspy.InputField()
       event_name: str = dspy.OutputField()
       date: str = dspy.OutputField()

   extract = dspy.Predict(ExtractEvent)
   ```

5. Optimize against a metric. GEPA needs a scoring function (`my_metric` here), training and validation sets of `dspy.Example` objects, and a reflection LM that rewrites prompts.

   ```python
   optimizer = dspy.GEPA(
       metric=my_metric,
       reflection_lm=dspy.LM("openai/gpt-5.4"),
       auto="light",
       num_threads=2,
   )
   optimized = optimizer.compile(haiku_generator, trainset=train, valset=val)
   optimized.save("haiku_v2.json")
   ```

## Key concepts

- **Signature**: the task contract, written as `"inputs -> outputs"` or as a class with `InputField` and `OutputField`. Field names and types act as hints to the model.
- **Module**: the strategy that runs a signature, such as `Predict`, `ChainOfThought`, `ReAct`, `ProgramOfThought`, or `CodeAct`. You compose your own by subclassing `dspy.Module` and writing `forward()`.
- **LM**: `dspy.LM` wraps a LiteLLM model string. `dspy.configure` sets the default; `dspy.context` overrides it locally.
- **Adapter**: turns a signature and inputs into messages and parses the reply. `ChatAdapter` is the default; JSON and XML adapters exist.
- **Example and metric**: `dspy.Example` holds labeled data; a metric is a Python function that scores a prediction.
- **Optimizer**: tunes instructions and demonstrations against a metric. GEPA uses a reflection LM to propose better prompts.
- **Caching and history**: identical calls are cached by default, and `dspy.inspect_history` shows past prompts and replies.

## Security notes

- Some modules run model-written code. `ProgramOfThought`, `CodeAct`, and tools built on `dspy.PythonInterpreter` execute Python generated by the LM. The interpreter runs code in a Deno and Pyodide WebAssembly sandbox; grant only the access you need through `enable_read_paths`, `enable_write_paths`, `enable_env_vars`, and `enable_network_access`.
- [CVE-2025-12695](https://nvd.nist.gov/vuln/detail/CVE-2025-12695): an overly permissive sandbox configuration let attackers steal files when an agent consumed user input and used `PythonInterpreter` (dspy 3.0.3 and earlier, [GHSA-vvw2-h478-xwr3](https://github.com/advisories/GHSA-vvw2-h478-xwr3)). Upgrade, and never feed untrusted input to a code-executing module without isolation.
- In `ReAct`, tool results become part of the trajectory the model reasons over, so a poisoned web page or document can redirect later tool calls. Keep the tool list minimal, and constrain outputs with typed fields such as `Literal` values where you can.
- Dependency risk is real. DSPy depends on LiteLLM. In March 2026, litellm 1.82.7 and 1.82.8 on PyPI shipped credential-harvesting malware after an API token was exposed through a compromised Trivy dependency ([GHSA-5mg7-485q-xm76](https://github.com/advisories/GHSA-5mg7-485q-xm76)). Pin and hash-lock dependencies, and rotate any credentials present where those versions ran.
- Optimization sends your training examples and scores to the LM provider, including the reflection LM. Use a provider and model you trust with that data, and set spending limits; optimizers make many calls.
