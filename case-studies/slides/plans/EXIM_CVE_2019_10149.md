# Slide plan: Exim Return of the WIZard

- Study: case-studies/EXIM_CVE_2019_10149.md
- Cover title: Return of the WIZard / CVE-2019-10149 / Exim's long exposure
- Subtitle: How a mail server correction that shipped before anyone named it a security flaw became a distribution, verification and recovery problem.
- Published: 18 November 2026
- Notes: The cover frames a 2019 Exim flaw where the hard part was proving the fix reached each server, not writing it.

## BACKGROUND | What the flaw actually was
- Exim is a mail transfer agent that runs a large share of internet mail.
- A crafted recipient address reached command interpretation in deliver_message.
- The delivery process ran at high privilege, so execution inherited root-level authority.
- Qualys disclosed it as "The Return of the WIZard" in June 2019.
Caption: Evidence grade: Confirmed by Qualys research and the maintainer advisory.
Notes: The flaw let externally influenced address data cross a trust boundary into command execution.

## TIMELINE | Disclosure compressed the response window
The coordinated schedule collapsed after a leak forced an early public release.

| Date | Event |
| --- | --- |
| 27 May 2019 | Qualys reported the issue and a patch to maintainers |
| 29 May 2019 | CVE-2019-10149 assigned |
| 3 June 2019 | Maintainer announcement issued |
| 5 June 2019 | Public release moved up to 15:15 UTC after a leak |
| 11 June 2019 | Originally planned coordinated release date |
Caption: Evidence grade: Confirmed from the maintainer disclosure timeline.
Notes: A response plan tied to an expected date can go stale before technical details become broadly available.

## VERSIONS | Affected range and the fix
Stat: 4.87 | First default-affected release, April 2016
Stat: 4.91 | Last affected release
Stat: 4.92 | Fixed release, shipped 10 February 2019
- Older builds could be affected only if an experimental feature was enabled manually.
Caption: Evidence grade: Confirmed version history from Qualys.
Notes: The correction existed in 4.92 before its security significance was recognized.

## EXPLOITABILITY | Keep the local and remote cases distinct
Left: Local case
- Exploitable immediately on a default configuration.
- A local attacker reaches privileged delivery directly.
Right: Remote case
- The default remote path required holding a connection open about 7 days.
- Easier remote paths existed only under certain non-default configurations.
Caption: Evidence grade: Demonstrated by Qualys, which warned its methods might not be exhaustive.
Notes: Any claim that the flaw is "remotely exploitable" has to carry its configuration and timing qualifier.

## DISCOVERY | The fix preceded its security label
- Exim 4.92 corrected the underlying problem on 10 February 2019.
- The change shipped before researchers recognized its security weight.
- A code fix and an ecosystem-wide security response are separate events.
- The open question is which code and correction an installation actually runs.
Caption: Evidence grade: Confirmed by Qualys and the maintainer record.
Notes: This made the incident a problem of identifying, distributing and verifying a correction rather than writing one.

## EXPOSURE | Potential reach, not a victim count
Stat: 174k+ | UK Exim servers flagged, three-CVE scope
Stat: 3 | CVEs bundled in NCSC's October advisory
Stat: 0 | Verified CVE-2019-10149 victims in that count
- The NCSC figure covered CVE-2019-10149 alongside CVE-2019-15846 and CVE-2019-16928.
Caption: Evidence grade: Reported figure, Inferred exposure, not a CVE-specific victim census.
Notes: A broad exposure estimate is useful for planning but cannot be converted into an incident count.

## WORM | Microsoft documented an active worm
- Microsoft's 13 June 2019 account confirmed an active Linux worm exploiting Exim.
- An 18 June clarification separated customer IaaS instances from Azure services.
- Network filtering was described as partial protection, not a fix for the flaw.
- Reported exploitation stays distinct from a census of compromised hosts.
Caption: Evidence grade: Reported by Microsoft at specific dates and scopes.
Notes: Permitted sources could still reach vulnerable software, so filtering left the defect intact.

## ATTRIBUTION | Sandworm is a separate, later claim
- NSA's 28 May 2020 advisory named Russian GRU actors publicly known as Sandworm.
- It attributed exploitation to at least August 2019.
- Later scripts attempted privileged-account changes and altered security settings.
- One vulnerability can serve different actors without a single shared campaign.
Caption: Evidence grade: Reported as an attributed government assessment.
Notes: An organization investigating its own event should weigh the report's relevance without importing its attribution.

## EVIDENCE | How the reporting changed over time
Evidence moved from no observed use to confirmed exploitation across different dates.

| Source and date | What it reported |
| --- | --- |
| Maintainers, June 2019 | No evidence of active exploitation at disclosure |
| CERT-FR, 11 June 2019 | Known exploitation, urged rapid correction |
| Microsoft, 13 June 2019 | Confirmed an active Linux worm |
| NSA, 28 May 2020 | Attributed later activity to Sandworm |
Caption: Evidence grade: Confirmed sequence; individual claims graded at their source.
Notes: Preserving the order prevents a later status from being read back into an earlier decision.

## BACKPORTS | Package evidence beats version strings
- cPanel shipped a 4.91-based patched package on some older branches.
- Other cPanel branches moved to upstream 4.92.
- Amazon's ALAS-2019-1221 corrected its own package on 5 June 2019.
- An upstream version alone cannot settle the state of every distribution build.
Caption: Evidence grade: Confirmed from retained supplier documentation.
Notes: Verification means matching the installed package to the supplier's correction and confirming the running service uses it.

## RECOVERY | Patching and rebuilding trust differ
Left: Installing the fix
- Match the package to the supplier's documented correction.
- Confirm the running service uses the corrected component.
Right: Rebuilding trust
- Treat credible privileged execution as possible system-wide compromise.
- Prefer a known-good baseline when integrity cannot be established efficiently.
Caption: Evidence grade: Inferred, an original defensive framework built on the reviewed record.
Notes: Installing a correction and establishing confidence in an already exposed server are different work products.

## CONTINUITY | Inventory the whole mail path
- Inventory should follow mail flow, not stop at hosts labeled as email servers.
- Password resets, transaction notices and alerts may ride the same path.
- Queued messages are operational data, preserved before irreversible choices.
- A forgotten standby can restore an unpatched image during an outage.
Caption: Evidence grade: Inferred, original continuity guidance.
Notes: Technical restoration and business acceptance are related milestones, but one does not prove the other.

## GRADING | What each source does and does not say
Each claim is tied to the grade the reviewed evidence actually supports.

| Claim | Grade |
| --- | --- |
| Address data could reach command interpretation | Confirmed |
| Qualys demonstrated distinct exploitation paths | Demonstrated |
| An active worm exploited vulnerable Exim | Reported |
| Millions of Exim servers were potentially exposed | Inferred |
Caption: Evidence grade: Confirmed, Demonstrated, Reported and Inferred, kept separate by design.
Notes: Mixing grades is how a potential-exposure estimate turns into a false victim count.

## TAKEAWAYS | The durable lesson
- Separate patch-available from patch-deployed at every host.
- Record supplier evidence, the running component and the closure reason.
- Keep the qualifier attached to any "remotely exploitable" statement.
- Durable closure means ordinary operations cannot casually recreate the exposure.
Caption: Evidence grade: Inferred, the study's synthesized operational conclusion.
Notes: Version labels, cloud placement and a single successful update each answer only part of the responsibility.
