## EXECUTIVE SUMMARY | A crafted regular expression could run code on a GitLab server

- GitLab's critical patch of 12 October 2026 fixed code execution through a regular expression in CI/CD configuration.
- The bug is an integer overflow in Onigmo, the regular expression engine that ships with Ruby.
- GitLab patched the Ruby it bundles instead of moving to a new Ruby version.
- CISA's SSVC entry said exploitation was active on 13 October; KEV listed it on 29 October.
- In the lab, a vulnerable 19.4.1 and a fixed 19.4.2 printed the same Ruby version string.
Caption: Evidence grade: Confirmed for the flaw, fix and KEV listing; Reported for press and module prerequisites; Demonstrated for the lab.
Notes: Patch release [1]. Ruby root cause [5][6]. SSVC [3]. KEV [4]. Lab [33].

## PART 1 | The bug lives in Ruby's regular expression engine

- Ruby says CVE-2026-97229 and CVE-2026-93577 are the same bug: a compiled-pattern size overflow.
- Ruby PR #19020, merged 25 September 2026, fixed it upstream.
- The fix is present from Ruby 4.0.8, 3.4.12 and 3.3.13; Ruby recommends 4.0.9, 3.4.12 or 3.3.13.
- An application is affected only when it compiles a pattern from an attacker-controlled string.
- Ruby says Regexp.timeout does not protect and length limits are not a reliable defense.
Caption: A CI/CD system that evaluates user-written rules is exactly such a program (Inferred).
Notes: Ruby security post [5]. PR #19020 [6]. Who is affected and what does not protect [5]. The CI/CD inference is the study's own.

## PART 1 | "Unauthenticated" needs a footnote

Left: What the records say
- GitLab, NVD and KEV say an unauthenticated user can trigger it.
- The code runs as the git account, GitLab's detections say.
Right: What the public module says
- An attacker first needs an account that can push to a public project.
- An unauthenticated CI lint request then triggers the overflow.
- Each attempt allocates about 2 GiB and crashes a Puma worker.
Caption: Treat any internet-reachable instance as exposed; open sign-up and public projects make it easier (Inferred).
Notes: Vendor wording [1][2][4]. git account [19]. Module prerequisites and crash, Reported [11]. Conservative reading Inferred.

## PART 4 | The lab told vulnerable from fixed by the GitLab version

Left: What the lab saw
- The manifest read gitlab-ce 19.4.1 and gitlab-ce 19.4.2.
- A version-range check flagged 19.4.1 VULNERABLE and 19.4.2 not in range.
- Both printed ruby 3.3.12 with the same manifest checksum.
Right: How the lab ran
- GitLab's own Docker images, pinned by tag and digest.
- HTTP published only on loopback.
- Only version strings were read; no CI lint request or pattern was sent.
Caption: Lab of 4 November 2026. Exploitation was not exercised; the version check does not prove the overflow unreachable.
Notes: Setup and digests [33][14]. Version reads and verdicts [33]. Ruby string and checksum [33].

## DEFENDER VIEW | Find every GitLab and decide by the product version

Left: Find
- Linux package hosts: the first line of version-manifest.txt.
- Debian and RHEL families: the gitlab-ce or gitlab-ee package version.
- Docker hosts: gitlab/gitlab-ce and gitlab-ee image tags.
Right: Fix
- Upgrade to 19.4.3, 19.5.1 or later to cover CVE-2026-110264 too.
- For this CVE alone the floor is 19.2.8, 19.3.5 or 19.4.2; 19.4.1 is not enough.
- GitLab lists no workaround; back up first.
Caption: BleepingComputer's first report named 19.3.4; GitLab's page now names 19.3.5.
Notes: Version sources [15][16][33]. Fixed releases [1][10][19]. No workaround and backup [1][17]. 19.3.4 [12][1].

## DEFENDER VIEW | Hunt with GitLab's six detections, then rotate secrets

| Detection | Where to look |
|---|---|
| Workhorse worker crash | 502 on CI lint or GraphQL with no Rails log line |
| Regexp guard rejection | application_json.log warnings |
| GraphQL ciLint hostile regexp | graphql_json.log |
| Oversized non-ASCII path | api_json.log or production_json.log |
| Scripted client error burst | 5xx bursts on ci/lint |
| Onigmo native crash | Puma stderr and Sidekiq logs |
Caption: On any sign of code execution, rotate gitlab-secrets.json, CI/CD variables, runner tokens and access tokens.
Notes: Detections [19][20][21][22][23][24]. Response and rotation [19]. Startup 502s in the lab [33]. A successful exploit may leave no crash [24].

## CROSS-CUTTING THEMES | The vulnerable code was a dependency inside the product

- **Library flaws travel.** Every product that embeds the library inherits its bug, as with Log4Shell.
- **Version strings lie when vendors patch in place.** Trust the product version.
- **Incomplete fixes come in sequences.** After a compiler fix, plan to patch again.
- **Read "unauthenticated" closely.** It says where to harden: sign-up, tokens and public projects.
- **Lab work can stay safe.** A version-only comparison answered the defender's question.
