## EXECUTIVE SUMMARY | A Brotli decoder flaw reached Node.js services that decode br

- CVE-2026-111497 is an out-of-bounds write in Google's Brotli decoder, which Node.js bundles for node:zlib.
- .NET, Envoy, Istio, Bun, the Python and Go packages and the system library carry the same decoder.
- The fix sat unreleased on Brotli's default branch from 27 February until the 21 October 2026 releases.
- CISA added it to KEV on 27 October 2026, due 10 November.
- In the lab, Node.js 24.22.0 was flagged and 24.22.1 was not, yet both reported Brotli 1.2.0.
Caption: Evidence grade: Confirmed for the flaw, the fixes and KEV; Reported for the exploit write-ups; Demonstrated for the lab.
Notes: Flaw and carriers [1][2][3]. Fix commit and releases [5][6][7]. KEV [9]. Lab version check and verdicts [27].

## PART 1 | An invalid block switch looked like a need for more input

- A Brotli stream switches between block types inside a meta-block, reading a new type and count when one runs out.
- On an invalid switch the decoder reported a temporary need for more input, not a format error.
- The streaming decoder kept appending to an eight-byte internal buffer: the out-of-bounds write.
- The fix makes the block-switch decoder return BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH.
Caption: The study reads the unchecked return value (CWE-252) as the cause and the write (CWE-787) as the effect (Inferred).
Notes: Block switches in RFC 7932 [28]. Mechanism per Node.js [3]. Fix commit 0ed4268 [7]. CWE reading Inferred [1][2].

## PART 1 | The attacker needs code that decodes attacker-supplied Brotli

Left: Server side
- Express 5 and body-parser 2 decode br request bodies in json() and raw() parsers.
- A request with Content-Encoding: br hands the body to the decoder.
- A bare node:http server does not decode Brotli bodies by itself.
Right: Client side
- Node's built-in fetch() decodes br responses from any server it calls.
- .NET names HttpClient automatic decompression and ASP.NET Core request decompression.
Caption: The CNA vector's AT:P fits this: a route or client must actually decode Brotli (Inferred).
Notes: Node.js reachability condition [3]. Server and client paths, Reported [16]. .NET paths [14]. AT:P [1].

## PART 4 | Two containers that differed only in the runtime

Left: Setup
- Same Dockerfile and two-route Express 5 app on node:24.22.0 and node:24.22.1.
- Both resolved express@5.3.0 with body-parser@2.4.0.
- Each published its port on 127.0.0.1 only.
Right: The test step, described
- A public read-only scanner sent one-byte controls and one large Brotli probe to each target.
- No code execution was attempted.
- The probe and its invocation are not shown.
Caption: Lab of 4 November 2026 UTC: loopback-only Docker targets, every container removed afterwards.
Notes: Setup capture 01-setup.txt [27]. Scanner commit bf2dc387 and the plan's read-only class [27]. Probe described, not shown.

## PART 4 | The Brotli version string cannot confirm the fix

Stat: 1.2.0 | process.versions.brotli on the vulnerable runtime
Stat: 1.2.0 | process.versions.brotli on the fixed runtime
- Node.js 24.22.1 cherry-picked one upstream commit into the Brotli copy it already had.
- A check that trusts the Brotli string flags fixed hosts and never sees the upgrade land.
- Only node --version told the two targets apart.
Caption: The body-parser range in one write-up was not the boundary either: 2.4.0 was still flagged.
Notes: Version check, Demonstrated [27]. Cherry-pick in the release notes [4]. ELLIO reports the same, Reported [17]. Body-parser range [16] against the lab [27], Inferred.

## DEFENDER VIEW | Upgrade is the fix; inventory is the control that works

Left: If you cannot upgrade today
- .NET documents removing the br provider and limiting HttpClient decompression.
- For Node.js, stripping br request bodies at a proxy is not vendor-documented and was not tested.
- None of these covers the client-side fetch() path.
Right: Detection limits
- Version inventory is the control that works.
- Decoder errors mark probes of hosts you already fixed.
- Crashes are a weak signal both ways; protect worker core dumps.
Caption: Treat any bridge as a way to buy days before the upgrade, not as the fix.
Notes: No Node.js workaround [3]. .NET workaround [14]. Bridges Inferred [27]. fetch() path [16]. Detection points [17][27][16].

## CROSS-CUTTING THEMES | Check the product, not the part

- **Check the product, not the part.** A cherry-picked fix leaves the component version where it was.
- **A quiet fix is a public fix.** An unreleased commit on a public branch is readable by anyone.
- **Absence of a crash is not absence of a hit.** The vulnerable runtime accepted the probe without an error.
- **Lab plans are hypotheses.** The plan expected a crash and a write-up implied a body-parser boundary; neither held.
- **One CVE, many patch owners.** Route the ticket per copy of the decoder, not per CVE.
