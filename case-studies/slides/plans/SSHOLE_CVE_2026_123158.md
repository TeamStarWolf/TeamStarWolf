## EXECUTIVE SUMMARY | A narrow flaw that the community fixed in a day

- On some Linux systems, sshd accepted a password login it should have refused.
- It needs musl libc, no PAM, password logins on, and an account whose password field is `*`.
- OpenSSH authored the fix the day it learned of the bug and shipped 10.6p2 the next day.
- Alpine, the musl maintainer and five embedded and source distributions followed within about a day.
- CISA listed it in KEV on 9 November with a three-day deadline and forensic triage.
Caption: Evidence grade: Confirmed for the flaw, fix and KEV listing; Reported for sensor telemetry and press.
Notes: Bug and fix [1][2][4]. Conditions [13]. Downstream [13][14][7][6][20][21][22][24][25]. KEV [34][35].

## PART 1 | An error token that looked like a password hash

- Without PAM, sshd compares the crypt() of the attempt with the stored password field.
- musl's crypt() returns `*` as an error indicator for an over-long key.
- That string matches the `*` field of a passwordless account.
- The fix rejects a match when the stored hash is shorter than a minimum length.
- Each party says the root cause is elsewhere: OpenSSH, musl and the trackers read it three ways.
Caption: All three readings can be true at once: a library returned a legitimate but unexpected value, and a caller treated it as a hash (Inferred).
Notes: Mechanism [13][6][8]. Fix [4][6]. Root-cause positions [1][4][7][8][10][15].

## PART 1 | All four conditions must hold

| Condition | What it means |
|---|---|
| sshd without PAM | openssh-server, or openssh-server-pam with UsePAM no |
| Password logins on | PasswordAuthentication yes, the default |
| A `*` account | root since about 3.16, key-only users, tiny-cloud alpine |
| A `$5$` or `$6$` hash | On any other local account |
Caption: Tiny-cloud images 3.18.11 to 3.24.3 ship an alpine user with passwordless doas: a path to root once any `$6$` hash exists.
Notes: Conditions and accounts as Alpine states them [13]. Tiny-cloud images [13]; the researcher says the same of AWS and Azure images, Reported [40].

## PART 3 | Attempts within hours, confirmed compromise only on sensors

Left: What the sensors counted
- GreyNoise: 33.7 million SSH sessions, 5 possible attempts, 26 confirmed chains from 8 addresses.
- SANS ISC: long-password attempts peaked at 713 on 6 November.
- Previdian: 26 attempts from 17 addresses in 12 countries.
Right: What attackers did after login
- Discovery, cloud metadata queries and shadow-file reads through doas.

- A new local account with a doas rule; a Python agent polling over HTTPS.

## PART 5 | The trackers disagree in both directions

Left: False positives
- The CPE range is "before 10.6p2", so version-only scanners flag glibc hosts that cannot be exploited.
- Debian lists glibc releases vulnerable at urgency unimportant.
- Ubuntu rates it High only because of KEV, with every release Not affected.
Right: False negatives
- NVD's CPE set names only Alpine, missing Yocto, Buildroot and appliance builds.
- Alpine backported the fix into older version strings, such as 3.24's 10.3_p1-r2.
- The OpenSSH security page carried no entry; only the release notes did.
Caption: Decide by libc, PAM and PasswordAuthentication, not by the version string (Inferred).
Notes: CPE [10][11]. Debian [17]. Ubuntu [18]. Backports [13]. Security page [5][1]. The scanner effects are Inferred.

## PART 5 | Waiting for KEV starts four days late

- BOD 26-04 gives 3 days plus forensic triage for an exposed, KEV-listed, total-impact flaw.
- The same table gives 14 days when the system is not exposed.
- The patch was public four days before the KEV listing.
- Sensor telemetry of exploitation came two to four days before it.
- A 30-day KEV cycle would leave an internet-facing host open 27 days past the deadline.
Caption: Intake has to watch release notes and mailing lists, not only CVE ids and KEV (Inferred).
Notes: BOD 26-04 Table 1 [37]. KEV [34]. Patch [1]. Telemetry [41][42][43]. The timing comparisons are Inferred.

## DEFENDER VIEW | Fix, restart, and bridge with key-only logins

Left: Fix
- Upgrade to 10.6p2 or the patched distribution package.
- Restart sshd: upgrading the package does not replace the running daemon.
- Update running tiny-cloud instances in place; rebuilt images do not fix them.
Right: Bridge
- Set PasswordAuthentication no after confirming key login works.
- Keep the default PermitRootLogin prohibit-password.
- Lock never-login accounts with `!` rather than `*`.
Caption: Restricting SSH exposure changes the BOD 26-04 clock but not the flaw (Inferred).
Notes: Fix and restart [1][13]. Instances [13]. Bridge [13][7]. Locking with ! Inferred from [13]. Exposure [37].

## DEFENDER VIEW | Hunt on the host, then triage as compromised

- Look for sshd "Accepted password" lines for accounts that have no password.
- Review doas use, new users, changed files and authorized keys.
- A long password in a log is not proof: brute-force scripts produced them before disclosure.
- If a login cannot be ruled out, treat the host as compromised.
- Rotate credentials and keys the host could read; remove attacker keys and accounts.
Caption: The KEV entry requires forensic triage.
Notes: Hunt and host review [13]. Long-password noise, Reported [42]. Rotation Inferred from [41][13]. KEV [34].

## CROSS-CUTTING THEMES | The interface between libraries is a security boundary

- **The embargo is shrinking.** A public exploit appeared before the CVE id existed.
- **Library seams matter.** An error token and a shadow convention collided in the caller.
- **One CVE, many meanings.** Context changes the risk more than the score does.
- **Defaults decide exposure.** Password logins on, root as `*`, passwordless doas.
- **Embedded is the long tail.** Firmware cycles sit outside distribution advisories.
Notes: Embargo [2][4][41]. Seam [13][7][8]. Trackers [15][17][18]. Defaults [13]. Embedded [24][25][11][9]. The lessons are Inferred.
