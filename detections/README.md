# Detections

> Detection content keyed to MITRE ATT&CK techniques: a small hand-curated set of ready-to-adapt SIEM and EDR queries, and the full set of detection strategies and analytics MITRE publishes in ATT&CK v19.2.

## What is here

| Path | Contents | How it is made |
|---|---|---|
| [TECHNIQUE_DETECTION_LIBRARY.md](/detections/TECHNIQUE_DETECTION_LIBRARY.md) | Per-technique queries for Splunk (SPL), Elastic (EQL/KQL), Microsoft Defender and Sentinel (KQL), Google SecOps (YARA-L), and CrowdStrike Falcon LogScale (CQL), each with its data source, a confidence rating, and the NIST SP 800-53 controls that mitigate the same technique | Hand-curated, seeded from SigmaHQ, Splunk security_content, Elastic detection-rules, Microsoft's Defender hunting queries, and Chronicle detection rules (credited on the page) |
| `technique-queries.json` | The same queries in machine-readable form, keyed by technique id, with a `_meta` block naming the platforms and sources | Hand-curated. No script renders the page from it, so an edit to one has to be made in the other |
| [strategies/](/detections/strategies/README.md) | One page per ATT&CK tactic listing MITRE's detection strategies and analytics for each technique: log sources, channels, detection logic, and tunable parameters | Generated by `scripts/generate_technique_detail_pages.py` from `data/attack/detection_strategies.jsonl` and `data/attack/analytics.jsonl` |

## How it is generated

`strategies/` is generated and must not be edited by hand. Change the data or the generator, then run:

```
python scripts/generate_technique_detail_pages.py
```

The same script writes `techniques/`. The Validate Data Files workflow runs it with `--check` on every pull request and fails if a committed page differs from the data, is missing, or is no longer produced.

The library page and `technique-queries.json` are hand-written. A change to a query goes through review like any other page; see [CONTRIBUTING.md](/CONTRIBUTING.md).

## How to use it

- Start from a technique: find its id in the [Technique Detection Library](/detections/TECHNIQUE_DETECTION_LIBRARY.md#technique-index) for a query you can adapt, then in [strategies/](/detections/strategies/README.md) for MITRE's own analytic and the telemetry it needs.
- Treat every query as a starting point. Field names, index names, and baselines differ between deployments; validate against your own data and tune false positives before you alert on it.
- Pair with the [Detection Rules Reference](/DETECTION_RULES_REFERENCE.md) for rule formats (Sigma, YARA, Suricata) and the [Build Your First Detection](/guides/BUILD_YOUR_FIRST_DETECTION.md) guide for an end-to-end workflow.
- The upstream rule projects remain the maintained source; check their licenses before you redistribute a rule.
