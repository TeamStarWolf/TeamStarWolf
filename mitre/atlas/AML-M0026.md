# AML.M0026: Manage AI Agent Service Access

<a id="amlm0026"></a>

ATLAS: [AML.M0026](https://atlas.mitre.org/mitigations/AML.M0026), addresses 12 techniques

Limit service AI agents--agents using independently assigned service or workload permissions--to explicitly authorized workflows. Agents may serve multiple users or act on requests, events, or schedules. Examples include service desk agents fulfilling support requests, operations agents restarting services after monitoring alerts, and reporting agents reading organizational data and publishing scheduled summaries. Apply least privilege to identities, roles, credentials, tools, and resources; permission to invoke an agent must not confer all its authority. Controls should include: - Dedicated Agent Identity: Use identifiable service or workload identities scoped to agent functions. Avoid unrestricted administrator accounts and broadly privileged identities shared across unrelated workflows. - Scoped Roles and Permissions: Use role-based or attribute-based controls to limit workflows to required operations and resources. Separate routine access from permission changes, credential management, security configuration, and deletion. - Workflow Initiation Authorization: Use trusted identity and authorization context to verify that requesters or triggers may initiate the specific workflow and affect its target resources. - Privilege Separation: Separate materially different workflows through distinct roles, credentials, or execution contexts. Prevent cross-workflow reuse of credentials or authorization state without explicit authorization. - Service Access Lifecycle Management: Limit elevated-access duration where supported, review grants as responsibilities change, and revoke unnecessary credentials or roles. Prevent unauthorized users and the agent itself from modifying permission configurations. An agent may perform operations unavailable directly to its requester, such as fulfilling an approved administrative request, but the requester must be authorized to initiate that workflow. Limit execution authority to the operations and resources needed to fulfill it. Use Enforce Access Controls for AI Agent Tools to enforce these restrictions when tools execute requests, and AI Agent Authority Expansion Controls to govern attempts to obtain additional authority during execution. Record the initiating user, application, service, event, or schedule, agent execution identity, authorization decision, and resulting activity through AI Telemetry Logging and Monitoring. Tools that may help implement these controls include: - Microsoft Entra ID: Provides service principals, managed identities, and application permissions for workloads. Workload identity federation supports authentication without stored application secrets where supported; Entra Agent ID provides agent-specific identities with directly assigned access. - Amazon Web Services IAM: Provides workload roles and temporary credentials scoped to required actions, resources, and conditions. IAM Access Analyzer supports permission review, policy validation, and policy generation from observed access.
