# AML.M0027: Manage User-Delegated AI Agent Access

<a id="amlm0027"></a>

ATLAS: [AML.M0027](https://atlas.mitre.org/mitigations/AML.M0027), addresses 12 techniques

Limit user-delegated AI agents to explicitly authorized tasks and permissions. Apply the principle of least privilege so that the agent receives only the access required for its designated tasks. The user's permissions establish an upper bound; the agent should not automatically receive every permission available to that user. Controls should include: - Agent Identity and User Association: Bind an identifiable agent or application identity to the authorizing user. Distinguish both identities in access decisions and activity records. - Scoped Delegation: Limit operations, resources, and services to the required subset of user permissions, using read-only access where sufficient. Derive scope from trusted configuration or authorization mechanisms, not the agent's interpretation of requests. - Credential and Session Management: Use scoped, short-lived credentials where supported. Keep credentials outside model-visible context, isolate them across users' agents and sessions, and avoid broadly privileged shared accounts. - Access Lifecycle Management: Review delegation when tasks or user permissions change, and reflect removed user permissions in effective agent access. Expire or revoke credentials and sessions when delegation ends, the agent is decommissioned, or compromise is suspected. Enforce delegated permissions through the systems that provide access to tools and resources. Use Enforce Access Controls for AI Agent Tools to ensure that tool calls remain within the user's delegation, including when tools invoke downstream services. Use AI Agent Authority Expansion Controls to prevent the agent from autonomously obtaining additional authority outside its approved scope. Tools that may help implement these controls include: - Microsoft Entra ID: Supports user-delegated permissions, user and administrator consent, and token acquisition on behalf of users. Entra Agent ID provides agent-specific identities with delegated access bounded by granted permissions and the user's authorized access. - Amazon Bedrock AgentCore Identity: Provides agent workload identities and centralized credential management for AWS and third-party services. User-authorized OAuth integrations support access on behalf of users.
