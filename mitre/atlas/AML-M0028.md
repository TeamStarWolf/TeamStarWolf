# AML.M0028: Enforce Access Controls for AI Agent Tools

<a id="amlm0028"></a>

ATLAS: [AML.M0028](https://atlas.mitre.org/mitigations/AML.M0028), addresses 12 techniques

Limit AI agent tool access to each caller's authorized, task-required operations and resources, including when tools are shared across agents, users, or tenants. Broader tool or backend privileges must not expand caller access. Enforce controls outside the model, in the tool implementation, MCP server, gateway, or underlying service. Enforce access controls outside the model: in the tool implementation, MCP server, access gateway, or underlying service. Controls should include: - Caller Authentication: Authenticate calling agents and derive identity, tenant, and delegation context from trusted authentication mechanisms, not model-generated arguments. - Request Authorization: Authorize each action on its target resource, separately controlling read, modify, and delete permissions. Deny requests when authorization cannot be established. - Delegated Access Enforcement: Enforce delegated permissions, trusted task restrictions, and tool policy through downstream calls. Use credentials scoped to each receiving service without expanding caller access. - Access Isolation: Isolate users' credentials, sessions, and authorization context. Select downstream credentials using verified caller context and prevent shared tool state from exposing another caller's resources. Tools that may help implement these controls include: - Open Policy Agent (OPA): Evaluates tool requests against caller identity, operations, resources, and trusted context. Tool services or gateways enforce the resulting least-privilege and caller-specific access decisions. - Cedar: Provides an authorization policy language and engine for evaluating caller actions on resources in context. Supports role- and attribute-based restrictions on tool operations and resources.
