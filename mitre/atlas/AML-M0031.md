# AML.M0031: Memory Hardening

<a id="amlm0031"></a>

ATLAS: [AML.M0031](https://atlas.mitre.org/mitigations/AML.M0031), addresses 2 techniques

Memory Hardening protects persistent state used by AI agents, including saved preferences, episodic or semantic memories, conversation summaries, stored chat history, and agent-managed experience stores. Unlike guardrails that evaluate content during an interaction, memory hardening controls how durable agent state is created, modified, isolated, audited, and recovered. Apply the following controls throughout the memory lifecycle, from creation and use through deletion and recovery: - Enforce memory access controls: Authenticate memory operations and authorize them within the appropriate user, tenant, agent, and session scope. - Set strong memory security policies: Enforce limits on memory size and update frequency, validate memory integrity, and define retention and deletion policies. - Preserve memory provenance: Record the source of all memory updates and preserve a history with known good versions. Quarantine or roll-back suspicious records. - Audit and monitor memory operations: Audit security relevant reads and writes. Monitor for unusual update frequency and repeated self-authored updates. Content filtering and protections against malicious prompts may be provided by Generative AI Guardrails, but does not replace memory access control, isolation, provenance, integrity, or recovery. Open-source tools that implement memory hardening controls include OWASP Agent Memory Guard and Microsoft Agent Governance Toolkit. Memory management and persistence tooling such as Mem0, and LangGraph Persistence can also support aspects of memory hardening.
