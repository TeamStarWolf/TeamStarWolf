# AML.T0018.001 — Modify AI Model Architecture

<a id="amlt0018001"></a>

**ATLAS tactics:** persistence, ai-attack-adaptation  
**Sub-technique of:** [AML.T0018 — Manipulate AI Model](/mitre/atlas/AML-T0018.md)  
**ATLAS:** [AML.T0018.001](https://atlas.mitre.org/techniques/AML.T0018.001)  

Adversaries may directly modify an AI model's architecture to re-define it's behavior. This can include adding or removing layers as well as adding pre or post-processing operations. The effects could include removing the ability to predict certain classes, adding erroneous operations to increase computation costs, or degrading performance. Additionally, a separate adversary-defined network could be injected into the computation graph, which can change the behavior based on the inputs, effectively creating a backdoor.

## Mitigations (3)

- [AML.M0005 — Control Access to AI Models and Data at Rest](/mitre/atlas/AML-M0005.md) — Establish access controls on internal model registries and limit internal access to production models.
- [AML.M0008 — Validate AI Model](/mitre/atlas/AML-M0008.md) — Validate that AI models perform as intended by testing for backdoor triggers, potential for data leakage, or adversarial influence.
- [AML.M0013 — Code Signing](/mitre/atlas/AML-M0013.md) — Enforce binary and application integrity with digital signature verification to prevent untrusted code from executing.
