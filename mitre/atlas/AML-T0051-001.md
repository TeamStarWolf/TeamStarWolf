# AML.T0051.001: Indirect

<a id="amlt0051001"></a>

ATLAS tactics: execution  
Sub-technique of: [AML.T0051: LLM Prompt Injection](/mitre/atlas/AML-T0051.md)  
ATLAS: [AML.T0051.001](https://atlas.mitre.org/techniques/AML.T0051.001)  

An adversary may inject prompts indirectly via a separate data channel that the LLM or AI agent ingests, such as text or multimedia pulled from documents, emails, databases or websites. These instructions originate from adversary-controlled content rather than the legitimate user, and are frequently hidden or obfuscated (See LLM Prompt Obfuscation) from the user, for example as invisible text. Adversaries may use this to hijack an agent or LLM in order to gain a foothold in the target system or to act against an unwitting user of that system, inheriting whatever privileges the AI system holds. Adversaries may also stage the lure that causes the content to be reached (See AI Agent Clickbait), or use the resulting foothold to establish persistence (See AI Agent Context Poisoning). Indirect prompt injections have been observed in the wild, with potential impact ranging from harmless pranks, to search engine optimization manipulation, data exfiltration, and destructive actions.

## Mitigations (3)

- [AML.M0024: AI Telemetry Logging and Monitoring](/mitre/atlas/AML-M0024.md): Implement logging and monitoring across the AI lifecycle to detect suspicious activity and support investigation.
- [AML.M0033: Input and Output Validation for AI Agent Components](/mitre/atlas/AML-M0033.md): Implement validation on inputs and outputs for the tools and data sources used by AI agents.
- [AML.M0035: AI Red Team](/mitre/atlas/AML-M0035.md): Establish an AI red team responsible for conducting recurring, authorized, and threat-informed red-teaming exercises to identify and remediate vulnerabilities in AI-enabled systems before deployment and throughout operation.
