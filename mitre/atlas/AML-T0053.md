# AML.T0053: AI Agent Tool Invocation

<a id="amlt0053"></a>

ATLAS tactics: execution, privilege-escalation, lateral-movement  
ATLAS: [AML.T0053](https://atlas.mitre.org/techniques/AML.T0053)  

Adversaries may use their access to an AI agent to invoke tools the agent has access to. LLMs are often connected to other services or resources via tools to increase their capabilities. Tools may include integrations with other applications, access to public or private data sources, and the ability to execute code. This may allow adversaries to execute API calls to integrated applications or services, providing the adversary with increased privileges on the system. Adversaries may take advantage of connected data sources to retrieve sensitive information. They may also use an LLM integrated with a command or script interpreter to execute arbitrary instructions. AI agents may also invoke applications indirectly through operating-system mechanisms such as deep links, app-intent URIs, universal links, or redirect chains. This can cause an installed application to open or perform an application-specific action even when that application was not selected as a direct agent tool, potentially avoiding normal user-confirmation workflows. An AI agent may exercise its own permissions or permissions delegated by a user on the adversary's behalf. When the agent treats an unauthorized request as sufficient authority to act, it may function as a privileged proxy, creating a confused-deputy condition. This authority can provide functional access to tools inaccessible to normal users. The adversary does not need to obtain the agent's credentials or impersonate the agent for this behavior to occur.

## Mitigations (13)

- [AML.M0020: Generative AI Guardrails](/mitre/atlas/AML-M0020.md): Guardrails are safety controls placed between users, tools, and generative AI models to evaluate prompts, retrieved context, model outputs, and agent actions before they are accepted, executed, or shown to a user.
- [AML.M0021: Generative AI Guidelines](/mitre/atlas/AML-M0021.md): Guidelines are instructions, policies, and behavioral constraints provided to a generative AI model to direct it toward desired outputs and away from unsafe, unreliable, or policy-violating behavior.
- [AML.M0022: Generative AI Model Alignment](/mitre/atlas/AML-M0022.md): Generative AI Model Alignment is the process of training or fine-tuning a generative model to guide its output toward a set of human values, goals, or ethical principles.
- [AML.M0024: AI Telemetry Logging and Monitoring](/mitre/atlas/AML-M0024.md): Implement logging and monitoring across the AI lifecycle to detect suspicious activity and support investigation.
- [AML.M0026: Manage AI Agent Service Access](/mitre/atlas/AML-M0026.md): Limit service AI agents--agents using independently assigned service or workload permissions--to explicitly authorized workflows.
- [AML.M0027: Manage User-Delegated AI Agent Access](/mitre/atlas/AML-M0027.md): Limit user-delegated AI agents to explicitly authorized tasks and permissions.
- [AML.M0028: Enforce Access Controls for AI Agent Tools](/mitre/atlas/AML-M0028.md): Limit AI agent tool access to each caller's authorized, task-required operations and resources, including when tools are shared across agents, users, or tenants.
- [AML.M0029: Human In-the-Loop for AI Agent Actions](/mitre/atlas/AML-M0029.md): Systems should require the user or another human stakeholder to approve AI agent actions before the agent takes them.
- [AML.M0030: Restrict AI Agent Tool Invocation on Untrusted Data](/mitre/atlas/AML-M0030.md): Untrusted data can contain prompt injections that invoke an AI agent's tools, potentially causing confidentiality, integrity or availability violations.
- [AML.M0032: Segmentation of AI Agent Components](/mitre/atlas/AML-M0032.md): Define enforceable security boundaries around AI agent tools, data sources, identities, and execution environments.
- [AML.M0033: Input and Output Validation for AI Agent Components](/mitre/atlas/AML-M0033.md): Implement validation on inputs and outputs for the tools and data sources used by AI agents.
- [AML.M0035: AI Red Team](/mitre/atlas/AML-M0035.md): Establish an AI red team responsible for conducting recurring, authorized, and threat-informed red-teaming exercises to identify and remediate vulnerabilities in AI-enabled systems before deployment and throughout operation.
- [AML.M0038: AI Agent Scope Drift Detection](/mitre/atlas/AML-M0038.md): Continuously evaluate whether an AI Agent's planned actions remain consistent with its current authorized objective throughout execution.
