# AML.T0080.000: Memory

<a id="amlt0080000"></a>

ATLAS tactics: persistence  
Sub-technique of: [AML.T0080: AI Agent Context Poisoning](/mitre/atlas/AML-T0080.md)  
ATLAS: [AML.T0080.000](https://atlas.mitre.org/techniques/AML.T0080.000)  

Adversaries may manipulate the memory of a large language model (LLM) in order to persist changes to the LLM across future chat sessions. Memory is a common feature in LLMs that allows them to remember information across chat sessions by utilizing a user-specific database. Because the memory is controlled via normal conversations with the user (e.g. "remember my preference for ...") an adversary can inject memories via Direct or Indirect Prompt Injection. Memories may contain malicious instructions (e.g. instructions that leak private conversations) or may promote the adversary's hidden agenda (e.g. manipulating the user).

## Mitigations (3)

- [AML.M0020: Generative AI Guardrails](/mitre/atlas/AML-M0020.md): Guardrails are safety controls placed between users, tools, and generative AI models to evaluate prompts, retrieved context, model outputs, and agent actions before they are accepted, executed, or shown to a user.
- [AML.M0031: Memory Hardening](/mitre/atlas/AML-M0031.md): Memory Hardening protects persistent state used by AI agents, including saved preferences, episodic or semantic memories, conversation summaries, stored chat history, and agent-managed experience stores.
- [AML.M0035: AI Red Team](/mitre/atlas/AML-M0035.md): Establish an AI red team responsible for conducting recurring, authorized, and threat-informed red-teaming exercises to identify and remediate vulnerabilities in AI-enabled systems before deployment and throughout operation.
