# AML.T0086 — Exfiltration via AI Agent Tool Invocation

<a id="amlt0086"></a>

**ATLAS tactics:** exfiltration  
**ATLAS:** [AML.T0086](https://atlas.mitre.org/techniques/AML.T0086)  

AI agent tools capable of performing write operations may be invoked to exfiltrate data to an adversary. Sensitive information can be encoded into the tool's input parameters and transmitted to an adversary-controlled location (such as an inbox, document, or server) as part of a seemingly legitimate action. Variants include sending emails, creating or modifying documents, updating CRM records, or even generating media such as images or videos. The invoked tool itself may be legitimate but invoked by an adversary via LLM Prompt Injection, or the tool may be malicious (See AI Agent Tool Poisoning. AI Agent Tool Poisoning can also be used manipulate the inputs and destination of a separate legitimate tool, invoked through normal usage by the victim.

## Mitigations (8)

- [AML.M0024 — AI Telemetry Logging](/mitre/atlas/AML-M0024.md) — Implement logging of inputs and outputs of deployed AI models.
- [AML.M0026 — Privileged AI Agent Permissions Configuration](/mitre/atlas/AML-M0026.md) — AI agents may be granted elevated privileges above that of a normal user to enable desired workflows.
- [AML.M0027 — Single-User AI Agent Permissions Configuration](/mitre/atlas/AML-M0027.md) — When deploying an AI agent that acts as a representative of a user and performs actions on their behalf, it is important to implement robust policies and controls on permissions and lifecycle management of the agent.
- [AML.M0028 — AI Agent Tools Permissions Configuration](/mitre/atlas/AML-M0028.md) — When deploying tools that will be shared across multiple AI agents, it is important to implement robust policies and controls on permissions for the tools.
- [AML.M0029 — Human In-the-Loop for AI Agent Actions](/mitre/atlas/AML-M0029.md) — Systems should require the user or another human stakeholder to approve AI agent actions before the agent takes them.
- [AML.M0030 — Restrict AI Agent Tool Invocation on Untrusted Data](/mitre/atlas/AML-M0030.md) — Untrusted data can contain prompt injections that invoke an AI agent's tools, potentially causing confidentiality, integrity or availability violations.
- [AML.M0032 — Segmentation of AI Agent Components](/mitre/atlas/AML-M0032.md) — Define security boundaries around agentic tools and data sources with methods such as API access, container isolation, code execution sandboxing, and rate limiting of tool invocation.
- [AML.M0033 — Input and Output Validation for AI Agent Components](/mitre/atlas/AML-M0033.md) — Implement validation on inputs and outputs for the tools and data sources used by AI agents.
