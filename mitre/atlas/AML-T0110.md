# AML.T0110: AI Agent Tool Poisoning

<a id="amlt0110"></a>

ATLAS tactics: persistence  
ATLAS: [AML.T0110](https://atlas.mitre.org/techniques/AML.T0110)  

Adversaries may poison tools used by AI agents by introducing or modifying malicious content or behavior in a tool's model-visible definition, executable implementation, or runtime responses. Tools may include built-in integrations, locally installed packages, remotely hosted services, Model Context Protocol (MCP) servers and tools, and agent skills or similar capability packages. A poisoned tool is represented or trusted as performing a benign function, but its definition, implementation, or responses cause agent behavior or tool-mediated effects to differ materially from the represented function. Poisoning may be present when a tool is first published, introduced through a Supply Chain Compromise, or added after adoption through an AI Supply Chain Rug Pull. Once the tool is installed, connected, or otherwise made available to the agent, it may provide the adversary with persistent influence over the agent's actions and external interactions. Adversaries may poison a tool's model-visible semantic interface, including its descriptions, schemas, parameter documentation, annotations, or agent-readable instructions (See Definition and Instructions). They may introduce hidden executable behavior that changes the effects of otherwise normal tool invocations (See Implementation). They may also cause a malicious or compromised tool to deliberately return content intended to influence the model's subsequent reasoning or actions (See Runtime Response). Poisoned tools may cause an agent to access sensitive data, alter the inputs or destinations of other tools, execute unauthorized commands, conceal actions from users, or exfiltrate information. Tool poisoning frequently enables other techniques such as LLM Prompt Injection, AI Agent Tool Invocation, and Exfiltration via AI Agent Tool Invocation. Tool poisoning is distinct from malicious data that a benign tool faithfully retrieves from an external or victim-controlled source (See AI Agent Tool Data Poisoning and LLM Prompt Injection: Indirect. Software that merely uses an agent tool package as a delivery vehicle for conventional malware, without subverting the tool's represented interface or operation, may be better described as a malicious package or software supply-chain compromise rather than AI Agent Tool Poisoning.
