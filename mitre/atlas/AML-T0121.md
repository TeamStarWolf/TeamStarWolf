# AML.T0121: AI Agent Environment Reconstruction

<a id="amlt0121"></a>

ATLAS tactics: persistence  
ATLAS: [AML.T0121](https://atlas.mitre.org/techniques/AML.T0121)  

An autonomous AI agent may reconstruct the environment needed to continue an existing operation after its execution environment is lost, reset, replaced, denied, or made unusable. The agent may recover or recreate tools, dependencies, configuration, credentials or access paths, communication or coordination resources, working artifacts, and externally stored operational state in order to resume the same objective.

## Mitigations (6)

- [AML.M0026: Manage AI Agent Service Access](/mitre/atlas/AML-M0026.md): Limit service AI agents--agents using independently assigned service or workload permissions--to explicitly authorized workflows.
- [AML.M0027: Manage User-Delegated AI Agent Access](/mitre/atlas/AML-M0027.md): Limit user-delegated AI agents to explicitly authorized tasks and permissions.
- [AML.M0028: Enforce Access Controls for AI Agent Tools](/mitre/atlas/AML-M0028.md): Limit AI agent tool access to each caller's authorized, task-required operations and resources, including when tools are shared across agents, users, or tenants.
- [AML.M0032: Segmentation of AI Agent Components](/mitre/atlas/AML-M0032.md): Define enforceable security boundaries around AI agent tools, data sources, identities, and execution environments.
- [AML.M0037: AI Agent Authority Expansion Controls](/mitre/atlas/AML-M0037.md): Limit an AI agent's ability to autonomously acquire additional authorities that expand its effective permissions during execution.
- [AML.M0043: AI Agent External Resource Lifecycle Management](/mitre/atlas/AML-M0043.md): Organizations should control external resources created or acquired by AI agents during execution by treating those resources as attributable, lifecycle-managed assets.
