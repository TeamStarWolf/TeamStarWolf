# AML.T0142: Event Triggered Execution

<a id="amlt0142"></a>

ATLAS tactics: persistence  
ATLAS: [AML.T0142](https://atlas.mitre.org/techniques/AML.T0142)  

Adversaries may establish persistence by creating or modifying event handlers, startup hooks, or associated configuration so that subsequent system or application activity automatically executes adversary-controlled code or commands. Triggers may include interpreter initialization, application execution, or other events processed by the affected mechanism. These modifications can allow malicious behavior to recur without another direct execution request from the adversary. In AI environments, adversaries may target hooks in the software and execution environments used for data processing, model training, evaluation, inference, or agent tool execution. For example, Python startup hooks may execute adversary-controlled code when a subsequent workflow or tool invocation starts an interpreter that processes the hook. Triggered code may perform malicious actions directly or emit content that is subsequently consumed by an AI system. Such content may contain fabricated approvals or instructions intended to manipulate the system's later behavior or make normally unobservable information available. AI Agents may also place triggers or trip-wires behind to observe, act on, or report conditions that the agent can no longer reach or are beyond its execution window.

## Mitigations (2)

- [AML.M0011: Restrict Library Loading](/mitre/atlas/AML-M0011.md): Prevent abuse of library loading mechanisms in the operating system and software to load untrusted code by configuring appropriate library loading mechanisms and investigating potential vulnerable software.
- [AML.M0013: Code Signing](/mitre/atlas/AML-M0013.md): Enforce binary and application integrity with digital signature verification to prevent untrusted code from executing.
