# T1027.005: Indicator Removal from Tools

<a id="t1027005"></a>

Tactics: stealth  
Platforms: Linux, macOS, Windows  
ATT&CK: [T1027.005](https://attack.mitre.org/techniques/T1027/005)  
Sub-technique of: [T1027: Obfuscated Files or Information](/mitre/techniques/T1027.md)  

Adversaries may remove indicators from tools if they believe their malicious tool was detected, quarantined, or otherwise curtailed. They can modify the tool by removing the indicator and using the updated version that is no longer detected by the target's defensive systems or subsequent targets that may use similar systems. A good example of this is when malware is detected with a file signature and quarantined by anti-virus software. An adversary who can determine that the malware was quarantined because of its file signature may modify the file to explicitly avoid that signature, and then re-use the malware.

## Detection

Detection strategies:

- Detection Strategy for Indicator Removal from Tools - Post-AV Evasion Modification

Analytics (3):

- Analytic 0540 (Windows): `WinEventLog:Application EventCode=1000` -> Application Log Content; `WinEventLog:Sysmon EventCode=1` -> Process Creation; `WinEventLog:Sysmon EventCode=11` -> File Creation
- Analytic 0541 (Linux): `auditd:SYSCALL execve` -> Process Creation; `auditd:SYSCALL open, rename` -> Process Modification; `linux:osquery file_events` -> File Metadata; `EDR:detection ThreatDetected, QuarantineLog` -> Application Log Content
- Analytic 0542 (macOS): `macos:unifiedlog quarantine or AV-related subsystem` -> Application Log Content; `macos:osquery file_events` -> File Metadata
