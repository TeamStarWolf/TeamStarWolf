# T1132 — Data Encoding

<a id="t1132"></a>

**Tactics:** command-and-control  
**Platforms:** Linux, macOS, Windows, ESXi  
**ATT&CK:** [T1132](https://attack.mitre.org/techniques/T1132)  

Adversaries may encode data to make the content of command and control traffic more difficult to detect. Command and control (C2) information can be encoded using a standard data encoding system.

## Detection

**Detection strategies:**

- Detection Strategy for Data Encoding in C2 Channels

**Analytics (4):**

- **Analytic 0302** (Windows) — `WinEventLog:Sysmon EventCode=3, 22` → Network Connection Creation; `WinEventLog:Sysmon EventCode=1` → Process Creation; `NSM:Flow Unusual Base64-encoded content in URI, headers, or POST body` → Network Traffic Content
- **Analytic 0303** (Linux) — `auditd:SYSCALL execve` → Process Creation; `NSM:Flow Base64 strings or gzip in URI, headers, or POST body` → Network Traffic Content; `linux:syslog Unusual outbound transfers from CLI tools like base64, gzip, or netcat` → Command Execution
- **Analytic 0304** (macOS) — `macos:unifiedlog base64 or curl processes chained within short execution window` → Command Execution; `macos:unifiedlog HTTP POST with encoded content in user-agent or cookie field` → Network Traffic Content
- **Analytic 0305** (ESXi) — `esxi:shell base64 or gzip use within shell session` → Command Execution; `esxi:vmkernel Outbound traffic using encoded payloads post-login` → Network Traffic Content; `ESXiLogs:authlog Unexpected login followed by encoding commands` → User Account Authentication
