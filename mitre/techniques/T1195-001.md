# T1195.001 — Compromise Software Dependencies and Development Tools

<a id="t1195001"></a>

**Tactics:** initial-access  
**Platforms:** Linux, macOS, Windows  
**ATT&CK:** [T1195.001](https://attack.mitre.org/techniques/T1195/001)  
**Sub-technique of:** [T1195 — Supply Chain Compromise](/mitre/techniques/T1195.md)  

Adversaries may manipulate software dependencies and development tools prior to receipt by a final consumer for the purpose of data or system compromise. Applications often depend on external software to function properly. Popular open source projects that are used as dependencies in many applications, such as pip and NPM packages, may be targeted as a means to add malicious code to users of the dependency. This may also include abandoned packages, which in some cases could be re-registered by threat actors after being removed by adversaries. Adversaries may also employ "typosquatting" or name-confusion by choosing names similar to existing popular libraries or packages in order to deceive a user. Additionally, CI/CD pipeline components, such as GitHub Actions, may be targeted in order to gain access to the building, testing, and deployment cycles of an application. By adding malicious code into a GitHub action, a threat actor may be able to collect runtime credentials (e.g., via [Proc Filesystem](https://attack.mitre.org/techniques/T1003/007)) or insert further malicious components into the build pipelines for a second-order supply chain compromise. As GitHub Actions are often dependent on other GitHub Actions, threat actors may be able to infect a large number of repositories via the compromise of a single Action. Targeting may be specific to a desired victim set or may be distributed to a broad set of consumers but only move on to additional tactics on specific victims.

## Mitigations (4)

- [M1013 — Application Developer Guidance](/mitre/mitigations/M1013.md) — Application Developer Guidance focuses on providing developers with the knowledge, tools, and best practices needed to write secure code, reduce vulnerabilities, and implement secure design principles.
- [M1016 — Vulnerability Scanning](/mitre/mitigations/M1016.md) — Vulnerability scanning involves the automated or manual assessment of systems, applications, and networks to identify misconfigurations, unpatched software, or other security weaknesses.
- [M1033 — Limit Software Installation](/mitre/mitigations/M1033.md) — Prevent users or groups from installing unauthorized or unapproved software to reduce the risk of introducing malicious or vulnerable applications.
- [M1051 — Update Software](/mitre/mitigations/M1051.md) — Software updates ensure systems are protected against known vulnerabilities by applying patches and upgrades provided by vendors.

## Detection

**Detection strategies:**

- Supply-chain tamper in dependencies/dev-tools (manager→write/install→first-run→egress)

**Analytics (3):**

- **Analytic 0021** (Windows) — `WinEventLog:Sysmon EventCode=1` → Process Creation; `WinEventLog:Sysmon EventCode=7` → Module Load; `WinEventLog:Sysmon EventCode=11` → File Creation; `WinEventLog:Sysmon EventCode=13, 14` → Windows Registry Key Modification; `WinEventLog:Microsoft-Windows-CodeIntegrity/Operational Invalid/Unsigned image when developer tool launches newly installed binaries` → File Metadata; `NSM:Flow First-time outbound connections to package registries or unknown hosts immediately after restore/build` → Network Traffic Flow
- **Analytic 0022** (Linux) — `auditd:SYSCALL execve` → Process Creation; `auditd:SYSCALL rename, chmod` → Process Modification; `journald:package dpkg/apt or yum/dnf transaction logs (install/update of build tools)` → File Metadata; `NSM:Flow First-time egress to new registries/CDNs post-install/build` → Network Traffic Flow
- **Analytic 0023** (macOS) — `macos:unifiedlog softwareupdated/homebrew/install logs, pkginstalld events` → File Metadata; `macos:endpointsecurity exec` → Process Creation; `NSM:Flow First-time egress to non-approved registries after dependency install` → Network Traffic Flow
