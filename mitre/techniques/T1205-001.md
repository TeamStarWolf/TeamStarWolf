# T1205.001 — Port Knocking

<a id="t1205001"></a>

**Tactics:** defense-evasion, persistence, command-and-control  
**Platforms:** Linux, macOS, Windows, Network Devices  
**ATT&CK:** [T1205.001](https://attack.mitre.org/techniques/T1205/001)  
**Sub-technique of:** [T1205 — Traffic Signaling](/mitre/techniques/T1205.md)  

Adversaries may use port knocking to hide open ports used for persistence or command and control. To enable a port, an adversary sends a series of attempted connections to a predefined sequence of closed ports. After the sequence is completed, opening a port is often accomplished by the host based firewall, but could also be implemented by custom software. This technique has been observed both for the dynamic opening of a listening port as well as the initiating of a connection to a listening server on a different system. The observation of the signal packets to trigger the communication can be conducted through different methods. One means, originally implemented by Cd00r, is to use the libpcap libraries to sniff for the packets in question. Another method leverages raw sockets, which enables the malware to use ports that are already open for use by other programs.

## Detection

**Detection strategies:**

- Port-knock → rule/daemon change → first successful connect (T1205.001)

**Analytics (4):**

- **Analytic 0842** (Windows) — `WinEventLog:Sysmon EventCode=1` → Process Creation; `WinEventLog:Sysmon EventCode=3, 22` → Network Connection Creation; `WinEventLog:Microsoft-Windows-Windows Firewall With Advanced Security/Firewall EventCode=2004, 2005, 2006` → Network Traffic Flow
- **Analytic 0843** (Linux) — `auditd:SYSCALL execve: Commands that alter firewall or start listeners: iptables|nft|ufw|firewall-cmd|pfctl|systemctl start sshd/telnet/dropbear; raw-socket/libpcap tools (tcpdump, tshark, nmap --raw).` → Process Creation; `auditd:SYSCALL socket/bind: New bind() to a previously closed port shortly after the sequence.` → Network Connection Creation; `NSM:Flow Knock pattern: repeated REJ/S0 across ≥MinSequenceLen ports from same src_ip then SF success.` → Network Traffic Flow
- **Analytic 0844** (macOS) — `macos:unifiedlog exec: Execution of pfctl, socketfilterfw, launchctl start ssh/telnet, libpcap consumers.` → Process Creation; `macos:unifiedlog Firewall/PF anchor load or rule change events.` → Network Traffic Flow; `NSM:Flow Sequence of REJ/S0 then SF success from same src_ip within TimeWindow.` → Network Connection Creation
- **Analytic 0845** (Network Devices) — `networkdevice:syslog Config/ACL changes, line vty transport input changes, telnet/ssh/http(s) enable, image/feature module changes.` → Network Traffic Flow; `NSM:Flow Series of denied/closed flows to distinct ports then success to mgmt port from same src_ip within TimeWindow.` → Network Connection Creation
