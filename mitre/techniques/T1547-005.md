# T1547.005 — Security Support Provider

<a id="t1547005"></a>

**Tactics:** persistence, privilege-escalation  
**Platforms:** Windows  
**ATT&CK:** [T1547.005](https://attack.mitre.org/techniques/T1547/005)  
**Sub-technique of:** [T1547 — Boot or Logon Autostart Execution](/mitre/techniques/T1547.md)  

Adversaries may abuse security support providers (SSPs) to execute DLLs when the system boots. Windows SSP DLLs are loaded into the Local Security Authority (LSA) process at system start.

## Mitigations (1)

- [M1025 — Privileged Process Integrity](/mitre/mitigations/M1025.md) — Privileged Process Integrity focuses on defending highly privileged processes (e.g., system services, antivirus, or authentication processes) from tampering, injection, or compromise by adversaries.

## Detection

**Detection strategies:**

- Registry and LSASS Monitoring for Security Support Provider Abuse

**Analytics (1):**

- **Analytic 1495** (Windows) — `WinEventLog:Security EventCode=4657` → Windows Registry Key Modification; `WinEventLog:Sysmon EventCode=7` → Module Load; `WinEventLog:Sysmon EventCode=1` → Process Creation
