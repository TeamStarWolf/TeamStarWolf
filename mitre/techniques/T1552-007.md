# T1552.007 — Container API

<a id="t1552007"></a>

**Tactics:** credential-access  
**Platforms:** Containers  
**ATT&CK:** [T1552.007](https://attack.mitre.org/techniques/T1552/007)  
**Sub-technique of:** [T1552 — Unsecured Credentials](/mitre/techniques/T1552.md)  

Adversaries may gather credentials via APIs within a containers environment. APIs in these environments, such as the Docker API and Kubernetes APIs, allow a user to remotely manage their container resources and cluster components. An adversary may access the Docker API to collect logs that contain credentials to cloud, container, and various other resources in the environment. An adversary with sufficient permissions, such as via a pod's service account, may also use the Kubernetes API to retrieve credentials from the Kubernetes API server. These credentials may include those needed for Docker API authentication or secrets from Kubernetes cluster components.

## Mitigations (4)

- [M1018 — User Account Management](/mitre/mitigations/M1018.md) — User Account Management involves implementing and enforcing policies for the lifecycle of user accounts, including creation, modification, and deactivation.
- [M1026 — Privileged Account Management](/mitre/mitigations/M1026.md) — Privileged Account Management focuses on implementing policies, controls, and tools to securely manage privileged accounts (e.g., SYSTEM, root, or administrative accounts).
- [M1030 — Network Segmentation](/mitre/mitigations/M1030.md) — Network segmentation involves dividing a network into smaller, isolated segments to control and limit the flow of traffic between devices, systems, and applications.
- [M1035 — Limit Access to Resource Over Network](/mitre/mitigations/M1035.md) — Restrict access to network resources, such as file shares, remote systems, and services, to only those users, accounts, or systems with a legitimate business requirement.

## Detection

**Detection strategies:**

- Detect Abuse of Container APIs for Credential Access

**Analytics (1):**

- **Analytic 0571** (Containers) — `docker:api docker logs access or container inspect commands from non-administrative users` → Command Execution; `kubernetes:apiserver get/list requests to /api/v1/secrets or /api/v1/namespaces/*/serviceaccounts` → User Account Authentication; `kubernetes:apiserver exec into pod followed by secret retrieval via API` → Process Creation; `kubernetes:orchestrator Access to orchestrator logs containing credentials (Docker/Kubernetes logs)` → Application Log Content
