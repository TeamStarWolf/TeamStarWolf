# T1568.003 — DNS Calculation

<a id="t1568003"></a>

**Tactics:** command-and-control  
**Platforms:** Linux, macOS, Windows, ESXi  
**ATT&CK:** [T1568.003](https://attack.mitre.org/techniques/T1568/003)  
**Sub-technique of:** [T1568 — Dynamic Resolution](/mitre/techniques/T1568.md)  

Adversaries may perform calculations on addresses returned in DNS results to determine which port and IP address to use for command and control, rather than relying on a predetermined port number or the actual returned IP address. A IP and/or port number calculation can be used to bypass egress filtering on a C2 channel. One implementation of [DNS Calculation](https://attack.mitre.org/techniques/T1568/003) is to take the first three octets of an IP address in a DNS response and use those values to calculate the port for command and control traffic.

**Analytics (4):**

- **Analytic 0728** (Windows) — `WinEventLog:Sysmon EventCode=3, 22` → Network Connection Creation; `WinEventLog:Sysmon EventCode=1` → Process Creation
- **Analytic 0729** (Linux) — `auditd:SYSCALL connect` → Network Connection Creation; `linux:syslog DNS response IPs followed by connections to non-standard calculated ports` → Network Traffic Content
- **Analytic 0730** (macOS) — `macos:unifiedlog DNS responses followed by connections to ports outside standard ranges` → Network Traffic Content; `macos:unifiedlog Unexpected processes making network calls based on DNS-derived ports` → Process Creation
- **Analytic 0731** (ESXi) — `esxi:syslog DNS resolution events leading to outbound traffic on unexpected ports` → Network Traffic Flow
