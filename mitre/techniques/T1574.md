# T1574 — Hijack Execution Flow

<a id="t1574"></a>

**Tactics:** persistence, privilege-escalation, defense-evasion  
**Platforms:** Linux, macOS, Windows  
**ATT&CK:** [T1574](https://attack.mitre.org/techniques/T1574)  

Adversaries may execute their own malicious payloads by hijacking the way operating systems run programs. Hijacking execution flow can be for the purposes of persistence, since this hijacked execution may reoccur over time.

**Team Star Wolf corpus signal (keyword-derived, n=529 HTB training machines):** observed on **13 machines (2.5%)** — Linux 8 / Windows 4. See the corpus deep-dive and detection-coverage matrix in the Lylat Labs range for tooling and detections.

## Detection

**Detection strategies:**

- Detection Strategy for Hijack Execution Flow across OS platforms.

**Analytics (3):**

- **Analytic 0609** (Windows) — `WinEventLog:Sysmon EventCode=1` → Process Creation; `WinEventLog:Sysmon EventCode=7` → Module Load; `WinEventLog:Security EventCode=4657` → Windows Registry Key Modification; `WinEventLog:Sysmon EventCode=11` → File Creation
- **Analytic 0610** (Linux) — `auditd:SYSCALL open/write syscalls targeting /etc/ld.so.preload or binaries in /usr/bin` → File Modification; `linux:syslog Service restart with modified executable path` → Service Metadata; `linux:osquery Process execution with LD_PRELOAD or modified library path` → Process Creation
- **Analytic 0611** (macOS) — `macos:unifiedlog Execution of process with DYLD_INSERT_LIBRARIES set` → Process Creation; `macos:unifiedlog Modified application plist or binary replacement in /Applications` → File Modification; `macos:unifiedlog Dylib loaded from abnormal location` → Module Load
