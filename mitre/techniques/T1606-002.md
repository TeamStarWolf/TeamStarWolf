# T1606.002: SAML Tokens

<a id="t1606002"></a>

Tactics: credential-access  
Platforms: SaaS, Windows, IaaS, Office Suite, Identity Provider  
ATT&CK: [T1606.002](https://attack.mitre.org/techniques/T1606/002)  
Sub-technique of: [T1606: Forge Web Credentials](/mitre/techniques/T1606.md)  

An adversary may forge SAML tokens with any permissions claims and lifetimes if they possess a valid SAML token-signing certificate. The default lifetime of a SAML token is one hour, but the validity period can be specified in the <code>NotOnOrAfter</code> value of the <code>conditions...</code> element in a token. This value can be changed using the <code>AccessTokenLifetime</code> in a <code>LifetimeTokenPolicy</code>. Forged SAML tokens enable adversaries to authenticate across services that use SAML 2.0 as an SSO (single sign-on) mechanism. An adversary may utilize [Private Keys](https://attack.mitre.org/techniques/T1552/004) to compromise an organization's token-signing certificate to create forged SAML tokens. If the adversary has sufficient permissions to establish a new federation trust with their own Active Directory Federation Services (AD FS) server, they may instead generate their own trusted token-signing certificate. This differs from [Steal Application Access Token](https://attack.mitre.org/techniques/T1528) and other similar behaviors in that the tokens are new and forged by the adversary, rather than stolen or intercepted from legitimate users. An adversary may gain administrative Entra ID privileges if a SAML token is forged which claims to represent a highly privileged account. This may lead to [Use Alternate Authentication Material](https://attack.mitre.org/techniques/T1550), which may bypass multi-factor and other authentication protection mechanisms.

## Mitigations (4)

- [M1015: Active Directory Configuration](/mitre/mitigations/M1015.md): Implement robust Active Directory (AD) configurations using group policies to secure user accounts, control access, and minimize the attack surface.
- [M1018: User Account Management](/mitre/mitigations/M1018.md): User Account Management involves implementing and enforcing policies for the lifecycle of user accounts, including creation, modification, and deactivation.
- [M1026: Privileged Account Management](/mitre/mitigations/M1026.md): Privileged Account Management focuses on implementing policies, controls, and tools to securely manage privileged accounts (e.g., SYSTEM, root, or administrative accounts).
- [M1047: Audit](/mitre/mitigations/M1047.md): Auditing is the process of recording activity and systematically reviewing and analyzing the activity and system configurations.

## Detection

Detection strategies:

- Detection Strategy for Forged SAML Tokens

Analytics (5):

- Analytic 0418 (Identity Provider): `azure:signinlogs SAML-based login with anomalous issuer or NotOnOrAfter lifetime` -> Logon Session Metadata; `WinEventLog:Security EventCode=4769, 1200, 1202` -> User Account Authentication
- Analytic 0419 (IaaS): `AWS:CloudTrail AssumeRoleWithSAML` -> Web Credential Usage; `CloudTrail:Signin SAML login without corresponding IdP authentication log` -> Logon Session Creation
- Analytic 0420 (Windows): `WinEventLog:Security EventCode=4624, 4648` -> Logon Session Creation; `WinEventLog:ADFS Token issuance events showing anomalous claims or issuers` -> Web Credential Creation
- Analytic 0421 (SaaS): `saas:access SAML token accepted without preceding login challenge` -> Web Credential Usage; `m365:unified Abnormal user claims or unexpected elevated role assignment in SAML assertion` -> Logon Session Metadata
- Analytic 0422 (Office Suite): `m365:exchange Mailbox access using SAML token without corresponding MFA event` -> Web Credential Usage; `m365:sharepoint File access with forged or anomalous SAML claims` -> Logon Session Creation
