# T1700: AI-Enabled Exfiltration

<a id="t1700"></a>

Tactics: exfiltration  
Platforms: Windows, SaaS  
ATT&CK: [T1700](https://attack.mitre.org/techniques/T1700)  

> New in ATT&CK v20.0. MITRE added this technique in the current release. The overview, defender notes, references and related ATLAS techniques on this page are the library's own, last reviewed 2026-11-03; the NIST control and corpus signal data do not cover it yet.

An enterprise agent that can read mail, search a document store and call tools already holds everything an exfiltration path needs. This technique covers turning that agent against its owner, usually through a direct or indirect prompt injection, so that it sends data out through a tool it is allowed to use: an email, a web request, a rendered image or link whose URL carries the data, or a write to an outside repository.

The arXiv paper "The Framing Gap" (August 2026) shows indirect prompt-injection exfiltration getting past surface-level defenses in tool-using agents, Google's April 2026 survey describes the prompt injections already planted on public web pages, and Barracuda reported email attacks in October 2026 written to reach both the human reader and an AI assistant in the same message.

ATT&CK's definition: Adversaries may utilize Direct Prompt Injection, Indirect Prompt Injection or other methods to instruct enterprise AI agents to exfiltrate data. When enterprise systems incorporate the use of AI assistants or other AI agents, adversaries may abuse these systems to weaponize sanctioned tools available to the agent.

## Mitigations (3)

- [M1017: User Training](/mitre/mitigations/M1017.md): User Training involves educating employees and contractors on recognizing, reporting, and preventing cyber threats that rely on human interaction, such as phishing, social engineering, and other manipulative techniques.
- [M1022: Restrict File and Directory Permissions](/mitre/mitigations/M1022.md): Restricting file and directory permissions involves setting access controls at the file system level to limit which users, groups, or processes can read, write, or execute files.
- [M1048: Application Isolation and Sandboxing](/mitre/mitigations/M1048.md): Application Isolation and Sandboxing refers to the technique of restricting the execution of code to a controlled and isolated environment (e.g., a virtual environment, container, or sandbox).

## Detection

Detection strategies:

- Detect AI-Enabled Exfiltration

Analytics (3):

- Analytic 2078 (SaaS): `saas:audit Actual send/share/upload/write operation` -> Application Log Content; `AWS:bedrock AgentTrace.actionGroupInvocationInput` -> Application Log Content; `AWS:bedrock AgentTrace.knowledgeBaseLookupInput` -> Application Log Content
- Analytic 2079 (Windows): `WinEventLog:Security EventCode=4663, 4670, 4656` -> File Access; `WinEventLog:PowerShell EventCode=4103, 4104, 4105, 4106` -> Script Execution; `WinEventLog:Sysmon EventCode=1` -> Process Creation
- Analytic 2080 (Linux): `auditd:SYSCALL open/read` -> File Access; `auditd:SYSCALL EXECVE` -> Process Creation; `auditd:SYSCALL connect` -> Network Connection Creation

Defender notes (library): MITRE ships three analytics that follow data from the agent's access to a transfer outside approved flows. To make them workable, keep an inventory of each agent's tools, data scopes and allowed destinations; log tool calls with arguments; and alert on agent-initiated transfers to new domains, URLs with long encoded query strings, and outbound messages or uploads that quote content the agent retrieved from a sensitive store. Restricting what an agent may render or fetch (no arbitrary image or link URLs) closes the quietest channel.
