# F5

F5 delivers and secures applications. Its BIG-IP platform load-balances traffic,
protects web applications, and controls access, and F5 Distributed Cloud offers
the same classes of service from the cloud. A network and security team uses F5
to keep applications available and to defend them at the application layer.

## What it is and where it fits

F5 sits in the path between users and applications. It receives client traffic,
decides how to handle it, and forwards it to the right server. From that
position it balances load, inspects requests, and enforces access policy.

BIG-IP is the on-premises and virtual platform. It runs modules that each add a
function. Local Traffic Manager handles load balancing. Advanced WAF, formerly
ASM, protects web applications. Access Policy Manager controls user access. F5
Distributed Cloud provides delivery and security as cloud services.

For a security team, F5 is an application-delivery control and a web application
firewall. It is also an internet-facing device whose management plane and
firmware must be guarded and patched. Both roles matter to the program.

## Architecture and how it works

BIG-IP is built on a traffic-management foundation that intercepts and processes
connections. A virtual server receives client traffic on a defined address and
port. Profiles and policies attached to it decide how the traffic is handled.
The platform then forwards traffic to a pool of back-end servers.

Local Traffic Manager is the load-balancing module. It distributes connections
across a pool by a chosen method, monitors server health, and removes unhealthy
members. It can terminate TLS, so inspection and offload happen on the device.

Advanced WAF inspects HTTP requests and responses for application-layer attacks.
It uses signatures, positive-security policies, and behavioral protections. It
defends against injection, cross-site scripting, and automated abuse. See
`/WEB_APPLICATION_SECURITY_REFERENCE.md` for the attack classes it addresses.

Access Policy Manager enforces authentication and authorization in front of
applications. It builds access policies as flows that check identity, device,
and context before granting a session. It supports single sign-on and acts as a
policy enforcement point.

BIG-IP separates a data plane that processes traffic from a management plane that
handles configuration. The management plane hosts the web interface, SSH, and
the iControl API. F5 Distributed Cloud delivers comparable functions as a
service, so the vendor runs the underlying infrastructure.

## Key capabilities

- Load balancing and health monitoring through Local Traffic Manager.
- TLS termination and offload on the device.
- Web application firewall protection through Advanced WAF.
- Access control and single sign-on through Access Policy Manager.
- Traffic steering and manipulation through policies and iRules.
- Cloud-delivered delivery and security through F5 Distributed Cloud.
- API-driven configuration through iControl REST.
- High availability through device pairing and failover.

What is in force depends on the modules licensed and the tier. Advanced WAF,
Access Policy Manager, and other modules are separately licensed. Confirm which
modules are provisioned before assuming a protection is active.

## Deployment and operations

BIG-IP deploys as physical appliances, as virtual editions in private and public
clouds, and in container environments. Form factor changes capacity and
placement, not the module model. F5 Distributed Cloud is consumed as a service
with no appliance to run.

Operations center on configuration, policy tuning, and firmware currency.
Configuration covers virtual servers, pools, profiles, and policies. WAF policy
tuning is ongoing, since new applications and false positives require
adjustment.

Firmware currency is a central operational task. BIG-IP management interfaces
have a history of high-severity vulnerabilities, some exploited in the wild. A
device behind on patches is an exposed asset, not only a control. Track BIG-IP
versions against vendor advisories. See `/VULNERABILITY_MANAGEMENT_REFERENCE.md`
for tracking such assets.

High availability pairs devices so one takes over on failure. Configuration syncs
between members of a device group. Changes are made, validated, and then synced
across the pair.

## Integrations and data flow

BIG-IP produces traffic logs, WAF event logs, and access logs. These forward to
a SIEM such as Splunk for correlation and retention through logging profiles and
high-speed logging. See `/platforms/splunk.md` for the analytics destination.

Access Policy Manager integrates with identity providers and directories for
authentication. It reads user and group attributes to drive access decisions and
provides single sign-on to back-end applications. Advanced WAF can integrate with
vulnerability scanners to import findings and tune policy.

The iControl REST API exposes configuration and operational state. Automation
and infrastructure-as-code tooling manage virtual servers, pools, and policies
through this API. iRules and policies run custom logic in the traffic path.

F5 Distributed Cloud exchanges configuration and telemetry through its own
console and API. It can front applications across clouds and on-premises origins
from the F5 global network.

## Hardening and secure use

Isolate the management plane. The web interface, SSH, and the iControl API must
not be reachable from the internet or from general user networks. Management
interface exposure has been the entry point for serious BIG-IP compromises.
Restrict management to a dedicated network and known administrator addresses.

Keep firmware current. BIG-IP has had critical management-plane vulnerabilities,
including ones under active exploitation. Subscribe to vendor advisories and
patch management-affecting issues quickly.

Protect API credentials and tokens. A leaked iControl credential gives an
attacker device-level control, which maps to CWE-798, use of hard-coded
credentials. Store credentials in a secret manager, scope accounts to the least
privilege, and rotate them. Keep them out of scripts and source control.

Use role-based administration. Give each administrator the least access the role
needs, avoid shared accounts, and require multi-factor authentication. Separate
WAF policy authors from full device administrators where the roles allow.

Tune WAF policy for enforcement, not only detection. A policy left in
transparent or staging mode logs attacks without blocking them. Confirm that
enforced policies block, review signature staging, and check the false-positive
handling so protection is real.

## Where it fits in the program

F5 is an application-delivery and application-security control. It keeps
applications available, terminates and inspects traffic, protects web
applications at the edge, and gates access. It stands between users and the
services the business depends on.

For the program, each BIG-IP device and Distributed Cloud configuration is a
tracked asset with its own patch and policy state. The control that protects
applications is itself an internet-facing device that needs the same discipline
as any other. See `/INTERNET_FACING_SERVICES_REFERENCE.md` for exposure
tracking.
